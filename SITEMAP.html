3 · Mistake classes — what we found

The duplicate-Sumit bug was not a one-off. It belongs to a family that shows up in almost every product, so the whole app was audited against that family rather than patched at the one place it surfaced.

Found and fixed
  • Creating the same thing twice. Every "add" minted a new id with no check, so one Sumit became five accounts. Now staff, buses (by normalised registration), vendors, parts and drivers all warn with the matching records and say plainly that this makes a second record, not an update.
  • No in-flight lock. Exactly one guard existed across 232 actions. A slow button looks dead and gets pressed again — that double-counts a fuel fill or a supplier bill just as easily as it duplicates a person. The lock is now on the clicked element, in the one place every action passes through, so actions added later are covered without anyone remembering.
  • An auth failure reported as a network failure. A 12-hour session expiring showed "Offline", so a device silently received nothing for days while looking fine. It now drops the dead token and says "Sign in again".
  • Paging that stopped after one page. pull() ignored the server's more flag, so a device several pages behind got only the oldest records it lacked — and the newest, where a person added today always sits, never arrived.
  • Default data outranking live data. The bundled seed rewrote every row and stamped it as newest, resurrecting archived crew and making it permanent, because the server's correct copy could then never win. It now fills gaps only, respects deletions, and writes with a low timestamp.
  • A circular dependency in login. The login screen was built from local data only, so a person created on another device had no tile — and the tile is what you need in order to sign in and sync. It now asks the server directly.
  • No undo. There was no way to remove a staff account, so five Sumits were permanent. Removal now exists, guarded so you cannot remove yourself or the last owner.
  • Orphaning dependents. Archiving a driver mid-trip left that trip open with its allowance unreconciled; removing a mechanic left job cards assigned to a name that no longer exists. Both now say what is still open before they let you continue.
Audited and clean
  • Unguarded routes. Every screen has a permission entry except home and me (open by design) and crew documents, which is permission-or-self and checked per record. This class had bitten twice before and was fixed then.
  • Client-only permission checks. The server enforces writes independently per store and role, so a crafted request cannot do what the UI forbids.
  • Silent exception swallowing. 18 empty catch blocks, all on localStorage, history and service-worker calls — legitimately ignorable, none on a data-write path.
  • Crashing on a missing reference. Lookups degrade to "—" rather than throwing.
Known, accepted, worth knowing
  • Last-write-wins. Two devices editing one record concurrently: the later write survives and the other is told, but the earlier edit is gone. Acceptable for this app's shape; it would not be for a shared ledger.
  • A brand-new device with no network starts from the bundled roster. It heals on its first online load.
  • Aadhaar is masked everywhere and revealed one number at a time, but it is stored. That is a deliberate trade for a register that has to survive an RTO inspection.
  • Removing a staff account takes it off every login screen but leaves the server's own user row, because there is no delete endpoint. Login is only reachable by picking a name from the roster, so the account is unusable.

4 · Where the truth lives

One origin serves the app and the API: garage-saathi-sync.vercel.app, deploying on every push. Data is local-first in IndexedDB and synced to Postgres (Supabase) by rev cursor. Staff use the web app added to the home screen — the packaged native app bundles frozen code and cannot be updated, which is why it was retired.
